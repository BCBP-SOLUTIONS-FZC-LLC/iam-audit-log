# Contributing

This is an internal IAM microservice for the XpertPMS platform: the platform's compliance system of record. This guide covers development setup, how to extend the service, test requirements, and the PR process for `iam-audit-log`.

The LLD (`docs/lld/iam-lld-audit-log-service.md`) is the single source of truth. In the PR, cite the section or ID you implement (AL-INV-\*, AL-EVT-\*, AL-D\*, AL-1..AL-7, D-n). Do not diverge from the LLD in code; raise a spec gap in [`docs/implementation/BUILD_PLAN.md`](docs/implementation/BUILD_PLAN.md) §C instead (decisions D-1..D-21, gaps 1–46).

## Prerequisites

- Go 1.26.6+ (matches `go.mod`)
- Docker (required for the PostgreSQL 15 + floci integration tests via `testcontainers-go`)
- `golangci-lint` and `swag` are managed as Go tools (`go tool golangci-lint`, `go tool swag`), so no separate install is needed
- `GOPRIVATE=github.com/BCBP-SOLUTIONS-FZC-LLC/*` (private module access; also `GONOSUMDB` for the same prefix)
- An SSH key registered with the BCBP org, so `go mod download` can fetch `platform-events`, `platform-gincommon` and `platform-pgcommon`

## Development setup

```bash
git clone https://github.com/BCBP-SOLUTIONS-FZC-LLC/iam-audit-log
cd iam-audit-log
make setup      # copies .env-example → .env and installs .githooks/pre-commit
make tidy       # go mod tidy
make docker-up  # start PostgreSQL 15 + floci (SQS/SNS/S3/Glue, provisioned by scripts/init-floci.sh)
make lint       # verify the linter passes
make test       # unit + postgres + integration (requires Docker)
make run        # start cmd/server: API on :8080, /metrics on :9090
make run-reconciler JOB=reconcile   # or redaction-retry | redaction-sweep | processed-events-prune
```

To run only unit tests (no Docker required):

```bash
make test-unit
```

`make setup` installs `.githooks/pre-commit`, which runs `make tidy`, `fmt-check`, `vet` and `lint` before every commit. Re-run `make install-hooks` any time `.githooks/pre-commit` changes.

Host ports for the local stack are deliberately offset from the sibling services so they can run side by side: Postgres `5548`, floci `4573`. The service itself is `8080` (API) and `9090` (metrics). Container-internal ports are unchanged.

## Extending the service

### Adding a new audited event type (taxonomy row)

1. Add the `(topic, source_event_type) → entry_type` row, and the entry_type → retention-tier row, to `internal/core/domain/taxonomy.go` (LLD §7.1). The tier comes only from the taxonomy; a caller never chooses it (AL-INV-6/11).
2. If the producer registers a Glue schema, the codec resolves it by version at runtime (AL-D12). No code change is needed, but add a fixture for the new shape to the normaliser tests.
3. Add the message to `api/asyncapi.yaml` as a **receive** operation with `x-audit-entry-type` / `x-audit-retention-tier` (`TestAsyncAPI_NoSendOperations_ALINV10` and the taxonomy contract test check both).
4. Unknown types are never dropped: they persist as `<domain>.unknown` (AL-EVT-4). A new row only improves classification.

### Adding a new use case (service method)

1. Add the method signature to the relevant interface in `internal/core/port/` if it introduces a new repository or outbound capability.
2. Implement the method in `internal/core/service/`. Audit writes go **only** through `AuditWriter.Append` / `RedactionStore.AppendWithRedaction`, the single write path for bus and direct-write (AL-INV-2). Each one is one `pgcommon.RunInTx` bound to the entry's tenant.
3. Wire it in `cmd/server/main.go`, or a reconciler job in `cmd/reconciler/jobs/`.
4. Add unit tests next to the code, plus postgres/integration coverage under `test/` if it crosses layers.

### Adding a new HTTP endpoint

1. Add the handler in `internal/adapter/inbound/http/`, annotated with swag `@Summary`/`@Tags`/`@Router` comments. Every endpoint has a stable identifier (AL-n) in LLD §5.3. The OpenAPI spec (`docs/swagger/`) is generated from these annotations via `make swag`, not hand-authored.
2. Wire the route in `internal/adapter/inbound/http/router.go` (not `cmd/server/main.go`; main.go only constructs dependencies and calls `NewRouter`). Register it on the correct group: `/api/v1/audit/*` (tenant_admin/owner, `RequireAuditReader`) or `/api/v1/internal/*` (mesh-only, `RequireSystemRole`). This service has no operator group.
3. Confirm the role check runs **before** any DB access, and that the tenant comes from the gateway identity, never the path or body (except AL-5/AL-6's body tenant and AL-7's explicit `tenant_id`, which are bound to `app.tenant_id` so RLS still applies).
4. Run `make swag` and commit the regenerated `docs/swagger/*` alongside your change. CI's `make swag-check` fails a PR whose annotations diverge from them. Update the API overview table in `README.md`.

### Adding a new repository migration

1. Run `make migrate-create NAME=<description>`, which produces `NNNNNN_description.up.sql` / `.down.sql` in `internal/adapter/outbound/postgres/migrations/`. **Numbering is monotonic**: never reuse a number or re-order existing ones.
2. The embedded FS is recompiled on the next build, so no code change is needed. `cmd/server` applies migrations at startup through `MIGRATION_DATABASE_URL` (a direct, non-PgBouncer DSN; the runner's advisory lock is session-scoped).
3. **Privileged operations are narrow `SECURITY DEFINER` functions granted to exactly one role**, never broader grants (the D-1/D-2 pattern): `REVOKE ALL ... FROM PUBLIC`, then `GRANT EXECUTE` to `audit_app` or `audit_reconciler`. Partition DDL needs ownership of `audit_events`, so it lives in migrator-owned definer functions. A function owned by `audit_reconciler` needs the gap-34 Terraform membership (`docs/implementation/RELEASE_CHECKLIST.md`).
4. **`audit_app` never gets `UPDATE`/`DELETE` on `audit_events`** (AL-INV-1). `check-grants.sh` and `TestRLS_Case4_AppRoleCannotUpdateOrDelete_ALINV1` enforce it.
5. Every tenant-scoped table gets `ENABLE` + `FORCE ROW LEVEL SECURITY`, `REVOKE ALL FROM PUBLIC`, and a `tenant_isolation` policy on `rls_check_tenant(...)`. Add RLS cases to `test/postgres/`.
6. `audit_events` is **partitioned**: an index created on the parent cascades to every partition, and `CREATE INDEX CONCURRENTLY` is not supported on a partitioned parent. Plan index changes on populated months as per-partition `CONCURRENTLY` builds plus an `ATTACH`, in a reviewed release.
7. Update the migration round-trip test's expected version (`test/postgres/migrations_test.go`) and `test/unit/migrations_contract_test.go` if it checks the new objects.

### Adding a new reconciler job

1. Add the job body to `cmd/reconciler/jobs/` and register it in `jobs.Registry()`. It runs on the `audit_reconciler` pool only.
2. Return a non-zero error when the job cannot complete: a failed CronJob is the operational signal (RB-9).
3. Add a CronJob entry to `deploy/helm/values.yaml` (`concurrencyPolicy: Forbid`) and a contract test in `test/unit/deploy_contract_test.go`.

### Adding a new metric

1. Classify it with the Enterprise Platform Observability Standard decision tree. `platform_*` and `iam_*` names must already be ratified (`internal/adapter/outbound/metrics/registry.go`); never invent one (rules 11/12). Otherwise it is `iam_audit_log_*`.
2. Register it in `business.go` with `pLabels` / `sLabels`, never a hand-set `service` label, and use only `label_vocabulary` keys and values for shared metrics.
3. Add it to `deploy/monitoring/metric-registry.yaml` and the LLD §11 table. `TestMetricRegistry_Conformance` fails otherwise.
4. Renaming: emit old and new in parallel, and mark the old one `status: deprecated` with `replaced_by` and `sunset`. Move alerts, recording rules, SLOs, the dashboard and the HPA to the new name (the contract tests fail on a deprecated reference).

### Adding a new environment variable

1. Add it to `.env-example` with an inline comment explaining its purpose and accepted values.
2. Read and validate it in `internal/config/config.go` (`LoadServer` / `LoadReconciler`). **Never read `PG_*` or `SQS_*` yourself**: platform-pgcommon and platform-events own those (CI enforces it).
3. Add it to `deploy/helm/values.yaml` (`serverEnv` / `reconcilerEnv`) and update the Environment variables table in `README.md` and LLD §12.

All unit tests must pass without Docker (`make test-unit`). PostgreSQL and floci tests start real containers automatically. The full suite (`make test-ci` + `make test-e2e`) takes more than 10 minutes locally, so run it in the background.

Run the race detector before submitting a PR (`make ci` does this automatically via `test-ci`):

```bash

```

### Canonical test cases

Some tests are load-bearing for the service's security and correctness posture. Do not break them without a design conversation:

- **`test/postgres/rls_test.go`**: `TestRLS_Case1_MissingGUCReturnsZeroRows_ALINV3`, `…Case2_CrossTenantInsertRejected_ALINV3`, `…Case3_MalformedGUCReturnsZeroRows_ALINV3`, `…Case4_AppRoleCannotUpdateOrDelete_ALINV1`. RLS fails closed, and `audit_app` can never rewrite audit rows.
- **`test/postgres/guc_test.go::TestGUC_TransactionLocalNoLeakAcrossPooledBackend_ALINV3`**: `app.tenant_id` never survives COMMIT onto a pooled backend. The app pool must stay forced onto pgcommon's PgBouncer-mode path.
- **`test/postgres/ingest_test.go::TestIngest_ConcurrentSameKeyYieldsOneRow_ALINV4`**: exactly one row under a concurrent duplicate.
- **`internal/core/service/query_service_test.go::TestQuery_WindowClampIndependentOfTier_ALINV8`**: the plan window never touches storage.
- **`test/postgres/redaction_test.go::TestRedaction_Compliance7yUntouched_ALINV7`** and **`redaction_ingest_test.go::TestRedaction_LateArrivalRedactedOnIngest_D18`**: redaction never reaches `compliance_7y`, and a late row about an erased subject is redacted before insert.
- **`test/postgres/archive_test.go::TestReconciler_DropBlockedWhenUnverified_ALINV9`** and **`::TestReconciler_RefusesPendingRedaction_ALINV12`**: no partition is dropped unverified or with a pending redaction.
- **`api/asyncapi_test.go::TestAsyncAPI_NoSendOperations_ALINV10`**: the service publishes nothing.
- **`test/unit/metrics_registry_test.go::TestMetricRegistry_Conformance`**: every series complies with the Observability Standard.

Run a single test:

```bash
go test ./internal/core/service/... -run TestQuery_WindowClampIndependentOfTier_ALINV8 -v
go test ./test/postgres/... -tags=integration -run TestRLS_Case2_CrossTenantInsertRejected_ALINV3 -v
go test ./test/integration/... -tags=integration -run TestReconciler_ArchiveVerifyDrop_HappyPath -v
go test ./test/e2e/... -tags=e2e -run TestAL1_DirectWriteThenQueryReturnsEntry -v
```

### Coverage gate

CI enforces a single global statement-coverage gate of **95%** (`.github/scripts/coverage-gate.sh`, `COVERAGE_THRESHOLD`) on the merged `coverage.out` from the unit, postgres and integration suites, as part of the `validate-test` workflow. Coverage is measured over `./cmd/...`, `./internal/...` and `./pkg/...` (`COVER_PKG_LIST` in the Makefile). It currently sits at about 96.5%.

```bash
make cover-func   # per-function summary in the terminal
make cover        # HTML report
```

Aim for meaningful coverage where it matters (RLS-guarded repositories, definer functions, the ingest path, the archive state machine, redaction) rather than chasing 100% on trivial code.

### Testcontainers note

Postgres and floci tests start real containers, so Docker must be running. Pass `-short` to skip them without Docker:

```bash
go test -short ./...
```

**Shared floci.** The integration package runs one floci for all its tests. A test that asserts queue or DLQ counts must purge its own queues first, or filter on its own event ids, because earlier tests may have left messages behind.

### PgBouncer protocol note

The app pool always runs in pgcommon's PgBouncer mode (simple protocol), which is required for the transaction-local GUC (AL-INV-3). pgx then encodes a `[]byte` argument as bytea hex, which a `jsonb` column rejects. Bind `metadata` and `filter` as `string` (or `json.RawMessage` → `string`), never raw `[]byte` (BUILD_PLAN gap 28). Test seeding goes through `test/dbseed`, a superuser pool built on `pgcommon.NewPool` / `WithConn`.

## Guardrails and forbidden patterns

- **Do not commit `.env`.** It is in `.gitignore`, as are the `.claude/` runtime files.
- **Never write `SET app.tenant_id` in code.** `app.tenant_id` is bound transaction-locally by pgcommon (`pgcommon.WithGUCSet` + the forced PgBouncer mode). A session-scoped `SET` leaks one tenant's GUC to the next pooled checkout (AL-INV-3).
- **No `UPDATE`/`DELETE` path for `audit_app`** (AL-INV-1). The only rewrites are `apply_redaction()` / `sweep_redactions()` as `audit_reconciler`, column-limited to `metadata` / `actor_display`, and never on `compliance_7y` (AL-INV-7).
- **No SNS publisher or outbox, ever** (AL-INV-10). `check-forbidden-events-bypass.sh` and the asyncapi receive-only check fail the build.
- **Each composition root binds only its own DB role**: `cmd/server` never reads the reconciler DSN, and `cmd/reconciler` never reads the app DSN.
- **Logs, metrics and traces only through platform-gincommon.** Use the gincommon logger (`port.Logger`) and `gincommon.MetricsRegisterer()`; OTel and promhttp only in `outbound/telemetry`. No `log`, `slog`, zap or `fmt.Print` (`check-observability-confinement.sh`).
- **Database only through platform-pgcommon**: `NewPool` from `ConfigFromEnv`, transactions via `RunInTx*`/`WithTx`/`WithConn`, errors via `pgcommon.Is*`, migrations via `pgcommon/migrate` (`arch-lint.sh` database invariant).
- **Events only through platform-events**: `events.NewSQSConsumer` with `config.LoadSQS`, and dedup on `Envelope.ID` in the single `processed_events` writer (`check-forbidden-events-bypass.sh` §4).
- **Metrics follow the Observability Standard**: no unratified shared names, no hand-set `service` label, no unbounded or forbidden label keys (`TestMetricRegistry_*`).
- **No audit payload, `metadata` or PII in log calls** (§11; `TestLogHygiene_NoPayloadFields`).

## Branch naming

Feature branches follow one of these forms:

- `feat/<short-topic>`: new capability
- `fix/<short-topic>`: bug fix
- `docs/<short-topic>`: documentation-only change
- `chore/<short-topic>`: dependencies, tooling, CI, or refactors with no behavioural change

The initial LLD build used `phase-N/<topic>` branches, one per phase. Base new branches off the latest `main`. Long-running integration branches are used only for coordinated multi-service work; check with the maintainers before targeting anything other than `main`.

## Commit style

Keep messages concise and describe the *why*. Reference the LLD section, invariant or decision ID when it clarifies the change:

```
Refuse partition drop while a redaction task is pending

A pending UserDeleted task means hot rows may still carry PII; sealing
them into Object-Locked S3 would make the erasure unreachable. The drop
gate now checks audit_redaction_tasks under the same ACCESS EXCLUSIVE
lock as the count check. (LLD §8.5, AL-INV-12.)
```

Use a short imperative subject line (≤ 72 chars) and reference the area:

```
feat(query): serve archived months from sealed manifest objects (D-12, D-20)
fix(redaction): use a target-less ON CONFLICT so audit_app needs no SELECT (gap 35)
fix(reconciler): read partitions through the parent, bounded to the month (gap 39)
feat(metrics): align Tier-1 labels with the Platform Observability Registry (gap 46)
test(rls): add Case 2 cross-tenant INSERT rejection (AL-INV-3)
docs: update the Environment variables table for OPS_STATS_INTERVAL
```

## Deployment

This service is deployed as a containerised microservice: 3 replicas by default, and an optional HPA (`autoscaling.enabled`, 3–6 replicas on CPU 70% / memory 80%, plus opt-in RPS and audit-queue-depth metrics via `deploy/monitoring/prometheus-adapter-rule.yaml`). Releases go through the CI/CD pipeline:

**On push / PR (`ci.yml`):**
1. `validate-test` (race detector + the 95% coverage gate, go-arch-lint, swagger drift) and `validate-quality` (fmt/tidy/vet/lint/vuln/mod-verify plus every invariant script) run in parallel.
2. The Docker image is built once (`linux/amd64`, `gcr.io/distroless/static-debian12:nonroot`, both binaries).
3. The Trivy CVE scan and smoke tests (`smoke-tests.sh`, once per binary) run, gated on `validate-test` + `build-image`.
4. `pr-summary` posts the results on PRs; on `main` the image is pushed.

**On a `v*` tag (`release.yml`):** validate → build (CHANGELOG gate) → docker (CVE scan + CycloneDX SBOM + provenance + Cosign signing) → `deploy-gate` (under the `production-data-migrations` environment, since the server self-migrates the `audit` DB at startup) → publish (GitHub Release with the SBOM and SLSA provenance).

The Helm chart in `deploy/helm/` renders one Deployment plus the 4 CronJobs, all from the same image (`command: ["/iam-audit-log-reconciler"]`, `args: ["--job=<name>"]`). Before the first AWS deploy, complete [`docs/implementation/RELEASE_CHECKLIST.md`](docs/implementation/RELEASE_CHECKLIST.md): the Terraform role membership for migration `000007`, the bucket settings, the `iam` namespace and CronJob-failure alerting. Notify the platform team if a migration or breaking env-var change needs a coordinated rollout.
